# 缺失、冲突与运行失败恢复

## 先保住已有交付，再处理单项错误

每次合法增量都原子落盘。一个字段/来源/候选失败，不应清零或跳过其他候选。脚本失败时读实际错误，不重写最后可用 checkpoint 为“成功”；只有真正验证无误才可把状态升级。

## 状态分流

| 情形 | 采用状态/记录 | 可继续做的工作 | 禁止做法 |
|---|---|---|---|
| 输入或应提供材料不存在 | `missing_material`，对核心选择通常为 `partial` | 审查其他材料、列出具体缺失路径及影响 | 改成设备不存在、实验失败或自己补文件 |
| 文件存在但字段未写 | `not_stated` | 标未知并提出最小澄清问题 | 当 0/false，或当“没有实施” |
| 存在但不可读/加密/损坏 | `source_unreadable` | 用已有解析/渲染路径重试，说明错误 | 声称已读全文或引用记忆补页码 |
| 图像页/纯扫描无文本层 | `no_text_layer` 并记录尚未核实图形 | 检查资源清单并实际渲染/OCR | 只看文件名/模型先验｜假装已查看图 |
| 来源冲突 | `conflicting_evidence` | 保留双方条件和值，有限分支重算 | 取平均、选最方便来源或悄悄删除反证 |
| 有资料但不足判断 | `undetermined` | 列最少量需要补充的事实、影响与决策者 | 用模糊措辞伪装确定选择 |
| 数值缺组成/量纲冲突 | `unknown`/明确 `unit_mismatch` | 保留部分小计和行项目，核查合同单位 | 将部分小计写成总价；跨币种相加 |
| 有限域交集为空/组合全非法 | `infeasible`，列冲突的约束组 | 其他候选照审；给需批准的改动方向 | 取并集、连续插值、取中点或忽略联合约束 |
| 枚举超限或工具无法证明全部覆盖 | 覆盖不全导致 `undetermined` | 给出已检查的集合和精确剩余问题 | 静默抽样后称全域最优/全部通过 |
| 三个候选都明确违反硬约束 | 完成比较，`no_feasible_option` | 输出每版退出原因与需批准的备选变更 | 强行选“违规最少”或让总分补偿 |
| 三个候选均缺关键证据 | 运行可达完成但有未决，选择无法确认 | 列完整范围内检索和证据缺口 | 写成全部不可行、或强行多数投票 |
| 依赖任务成环/超预约容量 | `invalid`/`infeasible`，列具体任务 | 保持任务关系并求变更任务图/窗口 | 擅自打破依赖、重叠占用单个设备 |
| 任务/资源时长缺失 | `unknown` | 有依据的工序工期另算 | 默认小时/工作日、日历工期或到货日期 |
| 某脚本语法/IO/类型错误 | `tool_error` 或 `invalid_input`，视影响部分/失败 | 修正输入引用；失败报告不丢候选的其他字段 | 把工具报错当科学不可行，或反复盲目执行 |
| 时间/请求将耗尽 | `partial` + 未完成字段清单 | 保留最后一个可验证结果并停扩展 | 最后瞬间生成没有依据补齐的大段结果 |
| 某条目与研究目标确实无关 | `not_applicable` + 依据 | 节省成本，保留理由 | 与未说明或失败混淆 |

## 操作与工具恢复

### PDF

1. 看 `source-index.json` 的 `status/error/version`，先区分解析器不可用、加密、字节错误、空文本和 OCR 失败。
2. 优先用资源清单中实际存在的后端；未安装第三方包不可写成已安装。严格限制工作目录在给定材料与 `/app/work`。
3. 若渲染/OCR完成，保留真实页图/文本、工具版本、页范围和状态；引用新派生文本时也保留原 PDF 哈希和页码。
4. 仍失败时只限制相关结论，不要用文献标题去补具体方法参数。

### 输出契约

- `output_contract` 不在 case 中时，把实际任务描述准确转录为 `/app/work/contract.json`，给 `bootstrap/validate/patch` 显式传**同一个** `--contract`；原始任务与转录之间不确定的地方另记。bootstrap 状态会保存外部契约的路径与哈希，并在后续命令中恢复它；发现契约变化时拒绝混用，另用新工作/输出路径重新初始化。
- `bootstrap` 只能用于新建结果和状态。若已经存在结果或 checkpoint，先读取并继续增量修订，或另选全新工作/输出路径；重复初始化会拒绝覆盖，绝不以重置方式丢掉已有结果。
- 如果脚本不支持该契约表述，不硬套固定验证 Schema。使用脚本支持的 JSON Schema/字段说明映射，保留原始键名和结构；映射解释与问题写入运行记录。不支持的 Schema 关键词必须明确说明，不能在未校验它们的语义后宣告全通过。
- `bootstrap` 对必需数值、非空枚举没有诚实默认时会报错。不要改成 0 或随意选一；依据实际输入生成最小合法结构，记入变更记录，再继续审查。
- `patch` 校验失败时不覆盖上一结果，null/非数组补丁会以结构化错误拒绝。只修正失败操作，检查 JSON Pointer 层级和类型。`/case_id` 不能覆盖，输入哈希变了不能混用变更。
- 如果原始 Schema 的根对象禁止附加字段却缺少必需 `case_id`，不要私加字段造成“看似通过”。记录契约冲突并把身份写入原合同指定的位置或诚实的侧车，明确未完成项。

### 资源、算术与有限域

1. 单位换算只依据案例明示/可核实定义；先核对数量单位与计价单位，再复算各行。
2. 不自动分摊一次性费用、合并独立候选预算、将技术测量转作独立样本或给所有重复乘同一耗材量。
3. 脚本计算完成仅为进程完成；须查看逐计划 `feasible/infeasible/undetermined/error`、组合覆盖/警告及每个硬门。非零终止则保留原有值，不正确写选择。
4. 若成本或参数超出约束，不把该编号方案删掉。保留淘汰记录，再对可行集比较。全不可行时“无合格”比虚假首选更正确。
5. 精确小数内部不做中间重复金钱舍入。最终显示舍入不能改变硬门判断，除非合同明确规定计费/预算舍入规则。

### 版本和证据

- 原始输入哈希、候选 ID/版本、引用页/指针任一变动都要重新读取，不能沿用选好的结果。
- 未证实语义等价前，文件改名/项目重排不是科学不变；标记 `unresolved_mapping` 并重新映射。
- 新版本或修改建议与原始候选分开；原硬门不能被新假设悄悄改写。若为选择有效性需要新增候选，明确标记新增，不记成原始三版之一。

## 停止规则

当更长的背景检索不能改变契约/证据/算术/选择时停止检索。确保至少存在：

- 原始 `case_id` 和原要求字段（如果读取失败，记录无法做到的实际原因）；
- 所有真实版本的同构矩阵及状态；
- 每个硬门的证据/数值检查；
- 可验证的引用与来源范围、不确定性、变更记录；
- 入选者或“无合格/无法确认”的理由、落选理由、确认项。

只有必要的证据和实际输出复核都完成后才写完成。严重错误但仍有可用部分时产出诚实的部分结果并读回，始终优于伪造成功。
